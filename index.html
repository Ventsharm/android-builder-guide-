Android App Builder Setup Guide

Set up your signing key and private GitHub builder, then turn any HTTPS website into a signed Android APK and Google Play AAB.

1. Get your Android upload signing key

Google Play does not give you a .jks file with passwords. For new apps, Google Play can manage the final app-signing key, while you create and keep your own upload key in a .jks keystore.

  • Create an upload keystore using Android Studio or Java keytool.
  • When you create it, choose and safely save your keystore password, key password and key alias (for example Upload).
  • Keep the .jks file permanently. You will use the same upload key for future updates to that app.
  • When you upload your signed AAB to Google Play, Play App Signing can manage the key used to sign the APKs delivered to users.
Google Play help: Use Play App Signing

2. Requirements before you begin

  • ✅ A GitHub account.
  • ✅ A private GitHub repository that will run the Android builds.
  • ✅ An Android signing keystore (.jks).
  • ✅ Your keystore password, key password, and key alias.
  • ✅ A fine-grained GitHub Personal Access Token.
  • ✅ Any HTTPS website (PWA or ordinary website — GitHub Pages, FreeFlarum, Blogger, Firebase Hosting, etc.).
Important: The builder repository should be PRIVATE. It stores encrypted GitHub Actions secrets containing your Android signing information. Your actual website can still be completely public.

What the Android Builder can build

  • ✅ Website with a working service worker: built with Bubblewrap.
  • ✅ Service worker but no usable manifest: Bubblewrap is still used and the builder creates the manifest.
  • ✅ No service worker: automatically built as a WebView Android app.
  • ✅ Both routes produce a signed APK and Google Play AAB and target Android 16 / API 36.
You do not have to choose the build type. Enter the website address and the builder checks it automatically.

What this page actually does

A .jks file is an Android signing keystore. This page does not change it into HTML. It reads the file locally and converts the raw bytes into Base64 text.

Why Base64? GitHub Actions Secrets accept text, not file uploads. Base64 lets the private workflow recreate the original keystore file during a build.

Before converting your keystore

Use only your own keystore. Never share the keystore file, its Base64 text, passwords, or GitHub token with anyone.
  • You need your own Android signing keystore, normally ending in .jks or .keystore.
  • You need the keystore password.
  • You need the key password.
  • You need the key alias, for example Upload.
  • Your build repository should be private.

Create the GitHub access token (required)

The Android Builder app needs a fine-grained GitHub Personal Access Token so it can start your private GitHub Actions workflow. This token is separate from your keystore secrets.

  1. Open GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens.
  2. Create a new fine-grained token.
  3. Select Only select repositories and choose your private builder repository.
  4. Under Repository permissions, set Actions → Read and write. Leave Metadata → Read-only (required).
  5. Generate the token and copy it immediately.
  6. Open the Android Builder app and paste the token into the Fine-grained GitHub token box.
  7. The token is used to trigger your private build. Your signing key remains safely stored in your repository secrets.

Public vs Private repositories

Private builder repository:

  • Stores your encrypted GitHub Secrets.
  • Runs the GitHub Actions workflow.
  • Signs your APK and AAB.
  • Should remain private.

Your website:

  • Can be a PWA or an ordinary HTTPS website.
  • Can be hosted on GitHub Pages, FreeFlarum, Blogger, Firebase Hosting, or another web host.
  • Does not need to be private.

Add the GitHub secrets

  1. Open the private GitHub build repository.
  2. Go to Settings → Secrets and variables → Actions.
  3. Create a repository secret called KEYSTORE_BASE64 and paste the copied Base64 text.
  4. Create KEYSTORE_PASSWORD using the keystore password.
  5. Create KEY_PASSWORD using the signing-key password.
  6. Create KEY_ALIAS using the key alias, such as Upload.
  7. Delete any temporary Base64 text file or clipboard copy after saving the secret.

How the private workflow restores it

During the GitHub Actions build, the workflow decodes the secret back into the original keystore file:

printf '%s' "$KEYSTORE_BASE64" | base64 --decode > upload-keystore.jks

The temporary keystore is used to sign the APK and AAB, then removed before build artifacts are uploaded.

After setup

Open the Android Builder, enter the website address and app details, choose an icon, paste your GitHub token and press Build Android App. The builder automatically chooses Bubblewrap or WebView and creates the signed APK and AAB.

Important safety rules

  • Never put Base64 keystore text in a public repository.
  • Never add the keystore to index.html, JavaScript, README files, or workflow inputs.
  • Never upload the keystore as a downloadable artifact.
  • Keep the build repository private and limit collaborator access.
  • Use a fine-grained GitHub token limited to the one private build repository.
  • Enable two-factor authentication on the GitHub account.
